# cladenc works offline and self-hosted

`cladenc` has to work on a machine with no connection to the internet, with everything a directed evolution uses hosted by the person who runs it.

**Why:** No reason is recorded; the rule holds as it stands.

**How to apply:**

- Never propose that `cladenc` fetches, downloads or looks up a thing: not a dataset, not an image, not a model, not a harness. The person brings it, as a directory or a file on the machine that a flag names.
- Do not put a design that needs the internet to the user as one of the ways to decide between. The rule has decided against it, and offering it costs the user a reply.
- A dataset is brought by the person, and the flag that gives it names the whole of it, every task it holds, never one task.
- When a dataset is shown by example, show several tasks in it. An example that holds one task reads as though the flag named a task.

A model served somewhere else stays something a person may give, since the rule says what `cladenc` has to be able to do and not what a person may point it at. The rule reaches Docker: `cladenc` has Docker fetch no image, and has no flag for a registry, since the name of an image says which registry it is of.
