# The words about benchmarks

`cladenc` uses Harbor's terminology. The words it uses about benchmarks are benchmark, task, instruction, diversification prompt, workspace, sandbox, verifier, verifier environment, verifier sandbox, trial, result, pass, fail and inconclusive, completed, verdict, to benchmark, completion rate, holdout, non-holdout, selection and corroboration. The README and the manual page of `cladenc start`, `docs/man/man1/cladenc-start.1`, say what each word means, and the code says which file of a task holds what. No definition and no file name is written in a memory.

**Why:** On 2026-11-25 the user decided that `cladenc` uses Harbor's terminology from then on. Grader had been chosen as one of the industry's names five days before `cladenc` took up Harbor's task format, nothing had weighed it against Harbor's verifier, and the industry has more than one name for most of these things. `cladenc` reads Harbor's tasks, so a person who brings them already knows Harbor's words. A definition or a file name written both in a memory and in the repository drifts apart from the one in the repository when the code changes.

**How to apply:**

- Say the words in replies, issues, commits, the README, the help, the manual pages, what `cladenc` prints and the names in the code.
- Harbor's names are read from Harbor's documentation, which the README links, and not recalled.
- A thing that Harbor names and the list at the top does not takes Harbor's name. No question is put to the user for it, and the name is added to the list.
- Verifier replaced grader on 2026-11-25, in the repository as well. With it came the verifier environment and the verifier sandbox, and a verifier that has a sandbox of its own runs separately, after `separate` in `task.toml`. Grader, grade, graded and grading are never said.
- Sandbox replaced container on 2026-11-25, by the user's decision, in the repository as well: the place a harness or a verifier runs in is a sandbox, the flag is `--max-concurrent-sandboxes`, and the sandbox a verifier has to itself is the verifier sandbox. Container and verifier container are never said for it. Container is still said where a sandbox is not what is meant: in saying that a sandbox of `cladenc` is a Docker container, for the several containers of an environment that a Compose file describes, which Harbor calls a multi-container environment and `cladenc` refuses, for a command or a message of Docker's own, and for Docker's containers in general.
- Trial replaced attempt on 2026-11-25 as well, in the repository too: one harness working on one task, once, is a trial of the harness on the task. Attempt, attempted and attempting are never said for it. Trial is no verb: a harness has a trial on a task, a trial is started, carried out and ended, and a task is given a trial.
- Assessment, assess, statement, check, success and failure are never said for the words of the list. Score is never said for how one trial ended: result is.
- Instruction replaced task specification, decided on 2026-11-25: it is the text that a task brings and that a harness is given in a trial. It takes no word in front. A task has one instruction and every trial on the task is given the same one, so trial instruction is not said. Task specification and specification are never said for it. It is the word in the repository as well.
- The diversification prompt is the text that `cladenc` holds itself and gives a harness in a diversification, the one that asks the harness to improve its clone. Harbor has no name for it. On 2026-11-25 the user chose prompt for it, over instruction and self-modification instruction, and later that day named the step it belongs to a diversification, per [[a-diversification-has-a-progenitor-a-clone-and-a-child]]. It is never called an instruction, and the instruction of a task is never called a prompt. The primogenitor is given the diversification prompt as well in the diversification of an experiment, where it creates the singleton control group harness, per [[the-singleton-control-group-harness]]. It is the name in the repository as well.
- Harness stays, though Harbor's word for a program that completes tasks is agent: the user decided so on 2026-11-25. Agent is never said for a harness, per [[a-harness-is-not-called-a-coding-agent]].
- Verdict is the word for the number a verifier writes at the end of a trial, though Harbor's word for it is reward: the user decided so on 2026-11-25, with Harbor's word in front of them. It replaced score. Neither score nor reward is said for that number, and the files a verifier writes it in keep the names Harbor gives them. It is the word in the repository as well.
- Completion rate is the word for the part of a set of finished trials that passed. The report has one, the clade completion rate, over the finished trials of a clade on the selection tasks. The user chose it on 2026-11-26, knowing that no leaderboard was found to say it and that Harbor's number over a dataset is the mean of the rewards, which is another number: completion rate was built on completed, which was `cladenc`'s own word for the result that is now pass, while Harbor has only the verb to complete. It replaced clade score. Success rate, pass rate, resolution rate and accuracy are never said for it. It has kept its name since the results were renamed later that day, and nothing has changed that.
- Score is no word of `cladenc` any more: not for the number a verifier writes, not for a column of the report, and not as a verb. Nothing new is named a score.
- No harness is said to be scored, on the corroboration tasks or on any other. On 2026-11-26 the user decided that the sentences that said so take no verb in its place, not to benchmark either: they say only that nothing is chosen by the corroboration tasks. What happens on those tasks is the benchmarking that every harness has on every task, which is already said once, and a verb of its own made it read as a second act with a score behind it.
- One older word names a thing that Harbor names otherwise: benchmark is Harbor's dataset. It stays as it is until the user says that it changes. Put it to the user on its own, in a reply, with what changes in the repository under Harbor's name.
- What a harness works on is a task, with its instruction and its workspace. Project, repository and code base are never said for it, and the source code of a harness is called that. Workspace names the files of a task and nothing else: neither the outputs directory nor the directory a harness works in is called a workspace.
- A harness is benchmarked: the primogenitor is benchmarked, a child is benchmarked, `cladenc` benchmarks a harness. A sentence that has a harness having a trial on every task is wrong, not another way to say the same. That each task takes one trial is said once, where the word trial is explained, and trial stays the word wherever one trial is what a sentence is about, such as which trial starts next.
- The result of a trial is one of three: pass, fail or inconclusive. The user named them on 2026-11-26. They replaced completed, not completed and no verdict as the names of the results: in what `cladenc` records of a trial, in the columns and the keys of the report, in what `cladenc start` prints at the end of a trial, and in the names in the code. A trial passes, fails or is inconclusive, and the counts of the report are of the trials that passed, that failed and that were inconclusive.
- Fail is said only where the verifier judged what the harness left and wrote a verdict that is not 1. A trial whose verifier gave no verdict, because it left none that can be read or because it ran past its time limit, is inconclusive: nothing judged the work, so whether the harness completed the task is not known. The user decided so on 2026-11-26, after such a trial had been counted and described as not completed. No sentence, count, column or name says of an inconclusive trial that it failed or that the harness did not complete the task, and the finished trials that are left once those that passed are taken away are never called failed as a whole.
- Why a trial is inconclusive is its cause, which is recorded beside the result. Cause is a word the session chose for it, not one the user named.
- Completed is still said of a harness and a task: a harness completed a task where its trial on the task passed, as in the tasks at least one harness completed and in the completion rate. It is no longer the name of a result. A trial that has ended, whatever came of it, has finished.
- The tasks that are not held out are the non-holdout tasks, never the other tasks.
- The holdout tasks that `cladenc` chooses nothing by are the corroboration tasks, never test tasks, though test is the industry's word. Corroboration is taken from science: a claim is corroborated when it survives a test that could have refuted it, and corroborated does not mean proven. The holdout tasks that are left are the selection tasks, which artificial selection goes by, never pick or validation tasks.
- No word is coined for something that has a name.
- A thing that Harbor has no name for, and that the list does not hold, is named by the user, and the name is added to the list once chosen. Put the things to them one at a time, one question for each: say what `cladenc` does, what `cladenc` calls it today, and every name the industry has for it, with who uses which. Do not put several words into one choice, do not choose for them, and say plainly where a word they bring is not the industry's. Ask in the text of a reply and not with the question dialog, which holds too few options to list every name.
- What the user says about one of the words in passing describes the idea. It is not a definition: do not take it to the letter.
