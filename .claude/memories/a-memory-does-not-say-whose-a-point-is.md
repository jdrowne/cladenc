# A memory does not say whose a point is

A memory states its rule plainly. It does not sort what it holds into what the user said and what the session added: it has no section headed "What is mine, and not the user's", and no sentence that calls a point the session's own reading or one the user has not confirmed.

**Why:** On 2026-11-24 the user asked why the memories marked points as the session's or as the user's, and asked for it to stop. No reason came with the request. The marks had come from the instructions that Claude Code gives a session at its start, which say to label the session's own interpretations when it saves feedback, and from earlier memories that later ones copied. They were taken out of every memory that carried one.

**How to apply:**

- Write each point of a memory as the rule it is.
- In a memory, the instruction to label the session's own interpretations is not followed.
- The **Why:** line still tells what happened and what the user asked, restated per [[never-quote-the-user-verbatim]].
- The rule is about memories. A recommendation in an issue or in a reply is still said to be the session's, per [[a-contradiction-is-the-users-to-settle]] and [[what-is-left-open-is-filed-one-issue-each]].
