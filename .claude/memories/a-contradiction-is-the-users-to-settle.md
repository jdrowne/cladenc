# A contradiction is the user's to settle

Where two memories say opposite things, or a memory and an autopilot reminder or `.claude/skills/autopilot/SKILL.md` do, or a memory and the code disagree on what `cladenc` is meant to do, the user decides which one holds. The session does not choose a side, even where one side looks newer or better supported, and does not count the fix as one that needs no decision.

**Why:** The user's rule. Each side of a contradiction is a rule or a design someone set, and picking one drops the other without the user knowing.

**How to apply:** Put each contradiction to the user on its own: as an issue of its own, labelled `needs decision` per [[before-an-issue-is-labelled-needs-decision]] and labelled per [[issues-about-the-sessions-rules-are-labelled]], or in a reply, one per reply, per [[the-simplest-design-is-offered-first]]. Say what each side tells the session to do, which files hold each, and what changes under each answer. A recommendation may come with it, marked as mine. Rewrite the memories, the skill or the code only after the user answers. Mine, not the user's: a count or a name in a memory that the code has moved past, with no rule or design behind it, is no contradiction and is corrected per [[a-memory-says-what-holds-now]].
