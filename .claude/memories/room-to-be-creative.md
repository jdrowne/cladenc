# Room to be creative

Be creative in this repository. No rule limits the work to only what was asked: not planning, not filing, not doing.

**Why:** A rule of that kind holds the work back, and it generalizes too widely from single things the user turns down.

**How to apply:** Do not build such a rule from one thing the user turned down. Ideas beyond the literal ask are welcome: a better design, a test nobody listed, an improvement to the tool. A specific thing the user turned down stays turned down until they say otherwise; creativity is about new ideas, not about bringing back one the user turned down. An idea of the session's own is carried out in the work at hand and lands in the commit that closes the issue being worked on, per [[a-commit-closes-at-least-one-issue]]; it needs neither the user's leave nor an issue of its own. The session asks the user only where the idea needs a decision that is theirs to make, such as a new flag, per [[before-an-issue-is-labelled-needs-decision]]. The idea is never written into the body of an issue the user opened, per [[an-issue-is-brought-up-to-date-before-work]].
