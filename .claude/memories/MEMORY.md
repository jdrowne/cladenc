# Memory Index

- [Push to main](push-to-main.md) — commit/push directly to main, no feature branches or PRs; starting the autopilot counts as the ask, and so does asking for a change
- [Never quote the user verbatim](never-quote-the-user-verbatim.md) — restate what the user says in fresh words in memories, issues, commits, comments and summaries
- [A memory says what holds now](a-memory-says-what-holds-now.md) — a memory states the rule, its reason and how to apply it, and tells nothing of how the rule came about or what was done when
- [Room to be creative](room-to-be-creative.md) — the user wants creative work, not a narrow reading of the ask; no rule limits the work to only what was asked
- [lib/ stores shared code](lib-stores-shared-code.md) — code more than one consumer uses goes under lib/, as in the user's other repositories; here, code shared by the test tiers
- [The paper is a starting point](the-paper-is-a-starting-point.md) — keep the HGM paper's ideas, name things plainly and with biological words (directed evolution, artificial selection, assessment), and let cladenc leave the paper where a change improves it
- [Assessing is not scoring](assessing-is-not-scoring.md) — a harness is assessed on a task or a benchmark and scored a success or a failure; an assessment never succeeds, fails or has an outcome, and what a harness is given is its score
- [cladenc takes a primogenitor and a model](cladenc-takes-a-primogenitor-and-a-model.md) — the user's design: a person brings the primogenitor's source code, a model and one or more benchmarks, and cladenc does the self-improvement itself, in Docker, calling no model itself
- [cladenc works offline and self-hosted](cladenc-works-offline-and-self-hosted.md) — the user's rule: no connection to the internet is needed, cladenc fetches nothing, and the person brings each thing a directed evolution uses, the whole benchmark among them
- [The work is clean-room](the-work-is-clean-room.md) — the paper is the only source; never read the authors' code, the Darwin Gödel Machine code, or a port or derivative of either
- [Every build is for Linux arm64](every-build-is-for-linux-arm64.md) — what CI compiles, tests, packages and releases is for Linux arm64 and no other platform
- [The only package is a .deb](the-only-package-is-a-deb.md) — no RPM is made, tested or released, and nothing in CI runs on Fedora
- [Repositories outside jdrowne stay out of the record](repositories-outside-jdrowne-stay-out-of-the-record.md) — not mentioned in a memory, and nothing from one quoted in anything public
- [Working without subagents](working-without-subagents.md) — no Agent or Workflow call, whatever the work's size; denied in the tracked settings.json, lifted only by the user's own ask
- [The work does not wait for CI](the-work-does-not-wait-for-ci.md) — after a push go straight on, commits and pushes included; the organization's free-tier runners are shared, so a run can stay queued for hours
- [What CI can do is done in CI](what-ci-can-do-is-done-in-ci.md) — no workflow check is run locally before a push: no test tier, clippy, format check, coverage, markdownlint or assert tool
- [Every run is watched](every-run-is-watched.md) — each run a push starts gets a background watch to its end; the work goes on, and a failure is fixed when the watch reports it
- [Long-running commands in the background](long-running-commands-in-the-background.md) — a command that can take more than about a minute is a background Bash call or a Monitor, with a time limit, never followed by a foreground wait
- [cargo is not on the shell's PATH](cargo-is-not-on-the-shell-path.md) — Rust is installed in ~/.cargo/bin; put it on PATH before calling cargo, and do not install it again
- [Reminders drive the loop](reminders-drive-the-loop.md) — an autopilot reminder only for a rule that says what to do next when it fires, one rule and one action each; every other rule is a memory
- [The work in hand can be several issues](the-work-in-hand-can-be-several-issues.md) — the autopilot takes the lowest unblocked issue, alone or with others it chooses; a blocked issue joins only with all its open blockers
- [Issues have no fixed form](issues-have-no-fixed-form.md) — no house layout and no section owed; write each issue in whatever form lets a session that never saw the conversation act on it
- [Issues are sized to one context](issues-are-sized-to-one-context.md) — split a plan too large for one context into stand-alone issues, re-using the original, ordered by blocked_by edges
- [One indivisible problem per issue](one-indivisible-problem-per-issue.md) — an issue documenting more than one problem is split, re-using the issue as one of the splits
- [An issue is brought up to date before work](an-issue-is-brought-up-to-date-before-work.md) — correct its title and body against the code as it stands before working on it, without adding work it does not ask for
- [A blocked_by edge states a real block](a-blocked-by-edge-states-a-real-block.md) — only where the waiting issue cannot be finished until the other closes; written with gh api and -F issue_id
- [Before an issue is labelled needs decision](before-an-issue-is-labelled-needs-decision.md) — check the memories and the code first, then write into its body what a person has to decide
- [Tests are written before code](tests-are-written-before-code.md) — the tests of a change come first and land in the same commit as its code
- [The checks the code faces](the-checks-the-code-faces.md) — written to pass release.yml: no comments, one assertion per test, no silencing directive, no linter config file, no Rust file over 1000 lines, every line covered, clippy, rustfmt
- [A commit closes at least one issue](a-commit-closes-at-least-one-issue.md) — one or more, a Closes #N line each; only a failed run's fix and a change the user asks for directly close none
- [A failed run is fixed before other work](a-failed-run-is-fixed-before-other-work.md) — when a run of the session's own push is found to have failed, the fix is the next commit pushed
- [A push can leave its issues open](a-push-can-leave-its-issues-open.md) — after a push, read back each issue the commit closes and close by hand any still open
- [The first harness is the primogenitor](the-first-harness-is-the-primogenitor.md) — and a progenitor is the harness that procreates; the two are told apart, and parent is used for neither
- [A procreation has a progenitor, a copy and a child](a-procreation-has-a-progenitor-a-copy-and-a-child.md) — whatever is written about a procreation says which of the three harnesses it means
- [An issue says what is expected apart from what happens](an-issue-says-what-is-expected-apart-from-what-happens.md) — what is expected is written as expected, never as though it were so; the plain present is for what really happens
- [A directory stores](a-directory-stores.md) — a directory stores what is in it and is never said to hold it
- [A harness is not called a coding agent](a-harness-is-not-called-a-coding-agent.md) — say coding harness or agentic coding harness, and primogenitor for the one a directed evolution starts from
- [The simplest design is offered first](the-simplest-design-is-offered-first.md) — lead a decision with the plainest option, such as a command-line option, explained in short concrete steps with every word defined
- [An explanation says what happens](an-explanation-says-what-happens.md) — for the user, say who does what in everyday words: which harness procreates, a harness has been scored; not the noun phrases of the issues and the code
- [A directed evolution is started with cladenc start](a-directed-evolution-is-started-with-cladenc-start.md) — older issues call the sub-command `cladenc run` and mean `start`
- [A flag is not called an option](a-flag-is-not-called-an-option.md) — say flag for a `--name` argument; the README shows `cladenc` and each sub-command as a command block, then a table of its flags in alphabetical order, with text about a sub-command under it
- [No flag has a default](no-flag-has-a-default.md) — every flag that takes a value is required and nothing about a directed evolution is assumed; a default is never proposed, and the count of required flags is not a problem; the seed is no flag, `cladenc` draws it
- [A key is given in a file](a-key-is-given-in-a-file.md) — a secret such as a model's key reaches cladenc in a file that a flag names, never as a flag's value or in an environment variable
- [Paths follow the Linux filesystem convention](paths-follow-the-linux-filesystem-convention.md) — nothing at the top of the filesystem, in a container or on the machine; what a container works with under /var/lib/cladenc, records under /var/log/cladenc
- [cladenc does not run jobs](cladenc-does-not-run-jobs.md) — say it brings up a container, for a procreation or for an assessment; job in an older issue means one of those, and the code says action; it has no workers either, say the containers running at the same time
- [A harness procreates only once scored on every task](a-harness-procreates-only-once-scored-on-every-task.md) — the user's rule: a progenitor has been scored on every task of every benchmark; no smaller number of tasks and no flag for it is proposed
